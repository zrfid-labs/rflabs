# Законы РФ 2002–2026: для людей и не для людей

Информационный ресурс: все законопроекты и законы РФ с 2002 года, автоматически
обновляемые из официальной системы Госдумы (СОЗД, sozd.duma.gov.ru).

**Критерий классификации** (задан владельцем, зафиксирован здесь как основной):

- 🔴 **Не для людей** — человек отдаёт государству и не получает эквивалента:
  налоги, сборы, пошлины, поборы (утильсбор и пр.), штрафы, надзор,
  ограничения (в т.ч. интернета), новые обязанности.
- 🟢 **Для людей** — человек реально получает благо: выплаты, индексация,
  льготы, бесплатные услуги, гарантии, защита прав, снижение/отмена платежей.
- ⚪ **Неопределённые** — правило не даёт однозначного ответа.

Двухступенчатая классификация:

1. **Детерминированный словарь правил** (`parser/rules.json`) — без токенов,
   разметает большинство законов мгновенно.
2. **Бесплатный LLM без ключей** (`parser/llm_classify.py`, открытый шлюз
   Pollinations) — добивает то, что словарю неясно: ~200 запросов за ночной
   прогон, ответ кешируется в `data/llm_labels.json` и накапливается. LLM
   пишет и человеческое объяснение — оно и попадает в «вырезку» на карточке.

Ручная поправка всегда главнее: `parser/overrides.json` → `{"407017-3": "pro"}`.

## Что на сайте

- **Плитки-счётчики**: принято и действует; на рассмотрении; всего «не для
  людей»; всего «для людей».
- **Лента свежих законопроектов** (по дате внесения).
- **Канбан по стадиям**: Внесён → На рассмотрении → Принят Госдумой → Совет
  Федерации → У Президента → Опубликован (действует) → Архив.
- **Канбан по годам** (2002→2026) и **по темам** — виден объём принятого.
- **Вырезка на каждой карточке**: чем именно законопроект против людей
  (сработавшие признаки словаря) + пояснение из карточки Госдумы + ссылка на неё.
- **Сетка законов (Zettelkasten)**: связаны законопроекты, правящие один и тот
  же закон; узлы-созвездия с подписями базовых законов, клик — открыть в Госдуме.
- Поиск по названию, номеру, инициатору. По умолчанию открыта вкладка
  «Не для людей».

## Автономная работа

1. Создай репозиторий на GitHub и запушь содержимое папки.
2. Settings → Pages → Deploy from branch → `main` → `/ (root)`.
3. Всё. Ежедневный workflow `.github/workflows/update.yml` сам обходит СОЗД
   (все созывы, ~90 запросов), пересчитывает классификацию и коммитит
   обновлённые данные; сайт на GitHub Pages подхватывает их автоматически.

Локальный запуск:

```bash
python parser/fetch_sozd.py    # сбор данных (~5-10 минут)
python parser/classify.py      # классификация -> data/laws.json
cd site && python -m http.server 8000
```

## Структура

```
parser/fetch_sozd.py   # обход СОЗД (только stdlib)
parser/classify.py     # стадии + аудитория + темы
parser/rules.json      # словарь правил (редактируй тут)
parser/overrides.json  # ручные поправки по номерам
site/                  # статический сайт (vanilla JS, без зависимостей)
data/                  # laws_raw.json -> laws.json + meta.json
.github/workflows/     # ежедневное автообновление
```

## Заметки

- Стадия берётся из последнего события карточки СОЗД; «Опубликован» = закон
  подписан и опубликован, т.е. действует.
- Статусы «В архиве / снят / отозван / возвращён» попадают в колонку «Архив».
- СОЗД отдаёт данные порциями по 500 карточек; между запросами пауза 1.5 c.
